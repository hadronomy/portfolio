This post is a test fixture. It stays a draft forever, so it renders under
`astro dev` and never reaches the build, the feed or the sitemap. Its job is to
put every element the layout has to handle on one page — dense on purpose,
because spacing problems only show up when blocks sit next to each other.

The running text is 16/24 in `muted-foreground`. Anything that raises its voice
moves to `foreground`, and that single move carries the hierarchy. Read down the
page and check that the greys stay consistent, that nothing collides, and that
both themes hold.

# A first-level heading

The post title above is already the document's `h1`, so a post should never open
a second one. This is here because the layout still has to style the case, and a
specimen that skips a case is not a specimen.

## A second-level heading

Second-level headings open a passage. They take 48px above and 16px below, so
they bind to the text under them instead of floating between two blocks. This
paragraph exists to prove the binding.

A second paragraph, to show the 20px that separates two blocks of running text
from each other. It should read as a smaller gap than the one above the heading
— if it does not, the rhythm is wrong.

### A third-level heading

Third-level headings sit inside a passage rather than opening one, so they take
40px above. Some **bold text** for the weight and colour shift, some *italic
text*, an [inline link](/blog) to check the underline offset, and some
`inline code` to check that the chip does not push the line height around.

#### A fourth-level heading

Core has eight text styles and no size between body and the third-level
heading. Rather than invent a ninth, this level takes the kicker treatment — the
one place the design uses mono.

## Code

A plain block with a title and line numbers:

```css title="tokens.css" lineNumbers
:root {
  --background: 0 0% 100%;
  --foreground: 0 0% 7.1%;
  --muted-foreground: 0 0% 49.4%;
}
```

A type-checked block. Hover any identifier for its type; the `^?` query pins one
open:

```ts twoslash
type Post = { body?: string };

/** Whole minutes at 200 wpm, which is what the writing rows show. */
function readingMinutes(post: Post): number {
  const words = post.body?.trim().split(/\s+/).length ?? 0;
  return Math.max(1, Math.round(words / 200));
}

const minutes = readingMinutes({ body: 'one two three four five' });
//    ^?
```

the same component the home page uses.

## Maths

Inline maths, $c^2 = a^2 + b^2$, sits on the same baseline as the text around
it. Display maths gets its own block:

$$
L^* = 116 \, f\!\left(\frac{Y}{Y_n}\right) - 16
$$

That is the CIE lightness function. The whole palette is achromatic, so
lightness is the only channel doing any work[^1] — which is why a hue introduced
anywhere reads as a mistake rather than an accent.
